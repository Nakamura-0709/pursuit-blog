AWS CDK や ECS、Lambda などで ECR を活用する中で、**Docker イメージを push したはずなのに、ECR に登録されるのは "image"ではなく "image index"（manifest list）になってしまう**という現象があります。

この問題はエラーとして出力されるわけではないため、気づきにくく、**後段の処理でイメージが想定通りに動作しない、取得できない**などの形で影響が現れます。

本記事では、この現象の原因と、それを回避するための具体的な対処方法を紹介します。

---

## 現象：Docker buildx で build & push したイメージが image index になる

```bash
docker buildx build --platform linux/arm64 -t <your-ecr-repo>:tag .
docker push <your-ecr-repo>:tag
```

一見問題なく build / push が完了しますが、ECR 上で確認すると、**登録されたイメージが "image" ではなく "image index"
（manifest list）** になっています。

この状態だと、CDK 経由での Lambda デプロイや、ECS での明示的な `imageDigest` 参照がうまくいかないケースがあります。

### 具体例：manifest list として登録される

```json
{
  "schemaVersion": 2,
  "mediaType": "application/vnd.docker.distribution.manifest.list.v2+json",
  "manifests": [
    {
      "platform": {
        "architecture": "arm64",
        "os": "linux"
      },
      ...
    }
  ]
}
```

---

## 原因：buildx の `--platform` 指定による multi-platform 対応

Docker Buildx の `--platform` オプションを使ってビルドすると、BuildKit はそのイメージをマルチプラットフォーム対応にするため、デフォルトで
**manifest list（image index）** を生成します。

> たとえ `--platform` に **単一プラットフォーム（例：`linux/arm64`）** を指定しても、BuildKit は image index
> としてまとめてしまう仕様になっています。

---

## 解決策：`--provenance=false` を付けてビルドする

この現象を回避するには、`docker buildx build` において **`--provenance=false`** を明示的に指定します。これにより、manifest
list ではなく、従来通りの単一のイメージとして出力・push されます。

### 対処済みのコマンド例

```bash
docker buildx build --platform linux/arm64 --provenance=false -t <your-ecr-repo>:tag .
docker push <your-ecr-repo>:tag
```

この方法でビルドしたイメージは、ECR 上でも単一の image として登録され、後続のデプロイや digest 取得も問題なく動作するようになります。

---

## 実例：複数関数／環境への対応

複数の Lambda 関数やアプリ環境に対して、以下のようにすべて `--provenance=false` を明示的に適用することで、安定した挙動が得られました。

```bash
cd ./cdk/lib/functions/test-lambda
docker buildx build --platform linux/arm64 --provenance=false -t <masked-ecr>:latest .
docker push <masked-ecr>:latest
```

---

## 補足：なぜ `--provenance=false` で回避できるのか？

Docker BuildKit では、ビルド時に SLSA や SBOM などのソフトウェアサプライチェーン情報（provenance）をイメージに添付します。これが
`--platform` オプションと組み合わさると、manifest list として格納されやすくなります。

`--provenance=false` を明示することで、このメタ情報の添付が抑制され、**manifest list の生成も回避される**という副次的効果が得られる形です。

※ この仕様は BuildKitの設計に由来するもので、将来的に挙動が変わる可能性もあります。必要に応じて最新版の [Docker Buildx ドキュメント](https://docs.docker.com/buildx/working-with-buildx/)を参照してください。

|-----|---------------------------------------------------------------|
| 現象  | Docker イメージが image index（manifest list）として ECR に登録される         |
