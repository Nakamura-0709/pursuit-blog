## 対象読者

- AWS CDK v2 を使用してインフラを構築しているエンジニア
- 開発・本番など複数環境で異なる設定値を安全に管理したい方
- TypeScript の型システムを活かして構成管理を行いたい方

## 構築した環境・ツール名

- AWS Cloud Development Kit (CDK) v2
- TypeScript
- CDK Pipeline（CodePipeline を使用）
- 複数ステージ（例：`DevPipelineAPNE1Stage`、`ProdPipelineUSE1Stage`）

## 構築の目的・背景

AWS CDK を使ったインフラ構築において、開発環境・本番環境などステージごとに異なる設定値（例：アカウントID、VPC
CIDR、DB名など）を使う必要がある場面は多い。

初期は各スタックファイル内に直接ハードコードしていたが、以下の課題が発生した。

- 設定の重複や矛盾が増える
- ステージ追加時にコピペと修正が必要
- 設定ミスによるデプロイエラーが発生しやすい

これを解消するために、`config.ts` に全環境の設定を集約し、各スタックやステージから必要な設定を取得する設計とした。

## 前提条件

- OS: macOS 15.4
- Node.js: v22.14.0
- AWS CLI: v2.25.11
- AWS CDK CLI: v2.1007.0

## 使用したコマンドや設定手順

### 1. `config.ts` に環境ごとの設定を記述

```ts
export type Environment = "DevPipelineAPNE1Stage" | "ProdPipelineUSE1Stage";

type ConfigParameters = {
    env: { account: string; region: string };
    branch: string;
    db: { dbName: string };
};

interface ISystemConfig {
    getSystemConfig(): ConfigParameters;
}

class DevConfig implements ISystemConfig {
    getSystemConfig(): ConfigParameters {
        return {
            env: {account: "DEV_ACCOUNT_ID", region: "ap-northeast-1"},
            branch: "develop",
            db: {dbName: "DevDB"},
        };
    }
}

class ProdConfig implements ISystemConfig {
    getSystemConfig(): ConfigParameters {
        return {
            env: {account: "PROD_ACCOUNT_ID", region: "us-east-1"},
            branch: "main",
            db: {dbName: "ProdDB"},
        };
    }
}
```

### 2. Map を用いて環境IDと設定クラスを関連付け

```ts
const SystemMap = new Map<Environment, ISystemConfig>([
    ["DevPipelineAPNE1Stage", new DevConfig()],
    ["ProdPipelineUSE1Stage", new ProdConfig()],
]);

export const getSystemConfig = (env: Environment): ConfigParameters => {
    const config = SystemMap.get(env);
    if (!config) throw new Error(`Unknown environment: ${env}`);
    return config.getSystemConfig();
};
```

### 3. `cdk.ts` や `Stage` クラスから参照

```ts
const app = new cdk.App();
const config = getSystemConfig("DevPipelineAPNE1Stage");

new PipelineStack(app, "Dev", {
    env: config.env,
    branch: config.branch,
});
```

## よくあるトラブルと対処法

| トラブル内容                  | 原因                              | 解決策                          |
|-------------------------|---------------------------------|------------------------------|
| `undefined` を返してクラッシュする | Map に環境が登録されていない                | `SystemMap.set(...)` を確認する   |
| 環境名のタイポによりビルドエラー        | `Environment` 型に定義がない文字列を使用している | `as const` やリテラル型を活用して型安全にする |
| DB設定などが未反映              | `process.env` の未設定または誤設定        | `.env` や環境変数の定義を事前に確認する      |

## 補足・Tips

- TypeScript の型定義によって、設定の安全性と自動補完が強化される
- `.env` との併用で、シークレット情報の管理にも応用可能
- `pipeline-ap-northeast-1-stage.ts` など、ステージごとにクラスを分けることで構成を明確にできる

## 最後に環境が動作するか確認する方法

```sh
npx cdk synth
npx cdk deploy Dev
```

`cdk deploy` を実行し、出力される CloudFormation テンプレートおよびデプロイ先の設定値が、指定した環境のパラメータに基づいていることを確認する。

## まとめ

- `config.ts` によるパラメータ一元管理は、環境ごとに異なる設定値を安全・柔軟に扱うためのベストプラクティス
- TypeScript の型定義を活かすことで、記述ミスや漏れを未然に防止可能
- ステージが増えてもメンテナンス性を損なわずにスケールできる設計になる

この構成を導入することで、AWS CDK プロジェクトの信頼性と拡張性が大きく向上する。
