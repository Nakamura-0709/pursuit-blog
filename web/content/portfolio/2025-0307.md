## 学習の動機・背景

私の部署ではCDKを利用してAWS環境をデプロイしているが、先方のセキュリティポリシーによってはアクセスキーの共有が難しいケースがある。
その場合、先方のAWS環境に`cdk deploy`コマンドを利用して端末から直接デプロイはできない。

今回はその代替案としてCDK Pipelineの実装を行った。
これまでCodePipelineは主にECSやLambdaといったアプリケーションのデプロイを目的に使用されてきたが、CDK
Pipelineを利用すればインフラ基盤のデプロイも可能になる。
また、インフラ変更のトレーサビリティ向上・ヒューマンエラー削減も見込めるメリットもあるため導入を決意した背景もある。

## CDK Pipeline構築手順

1. **CDKプロジェクトの作成**
   `npx aws-cdk init app --language=typescript` でCDKアプリを初期化。
    - 参考：[Hello World](https://docs.aws.amazon.com/cdk/latest/guide/work-with-cdk-typescript.html)

2. **リソース定義の作成**
    - **VPC**：`networking.ts` にて定義

```typescript
// lib/constructs/networking.ts

import {aws_ec2 as ec2} from "aws-cdk-lib";
import {Construct} from "constructs";

export interface NetworkingProps {
}

export class Networking extends Construct {
    constructor(scope: Construct, id: string, props: NetworkingProps) {
        super(scope, id);

        new ec2.Vpc(this, "Vpc", {
            ipAddresses: ec2.IpAddresses.cidr("10.0.0/16"),
            createInternetGateway: true,
            defaultInstanceTenancy: ec2.DefaultInstanceTenancy.DEFAULT,
            enableDnsHostnames: true,
            enableDnsSupport: true,
            maxAzs: 2,
            subnetConfiguration: [
                {
                    cidrMask: 24,
                    name: "TestSubnet",
                    subnetType: ec2.SubnetType.PUBLIC,
                },
            ],
        });
    }
}
```

- **S3バケット**：`datastore.ts` にて定義

```typescript
// lib/constructs/datastore.ts

import * as s3 from "aws-cdk-lib/aws-s3";
import {Construct} from "constructs";

export interface DatastoreProps {
}

export class Datastore extends Construct {
    constructor(scope: Construct, id: string, props: DatastoreProps) {
        super(scope, id);

        new s3.Bucket(this, "DatastoreBucket", {
            autoDeleteObjects: true,
        });
    }
}
```

3. **スタック定義**
   `ap-northeast-1-stack.ts` にて、VPCやS3バケットを統合。スタックはリージョンごとに必ず分離する必要があるため、ファイル名は
   `ap-northeast-1-stack.ts` のようにリージョン由来にした。

```typescript
// lib/stacks/ap-northeast-1-stack.ts

import * as cdk from "aws-cdk-lib";
import type {Construct} from "constructs";
import {Datastore} from "../constructs/datastore";
import {Networking} from "../constructs/networking";
import type {StackProps} from "aws-cdk-lib";


export interface ApNortheast1StackProps extends StackProps {
}

export class ApNortheast1Stack extends cdk.Stack {
    constructor(scope: Construct, id: string, props: ApNortheast1StackProps) {
        super(scope, id, props);

        new Networking(this, "Networking", {});

        new Datastore(this, "Datastore", {});
    }
}
```

4. **ステージの作成**
   `ap-northeast-1-stage.ts` にて、上記スタックを `Stage` にまとめる。1ステージにつき1スタックを紐づけている。

```typescript
// lib/constructs/pipeline/stages/ap-norheast-1-stage.ts

import {Stage, type StageProps} from "aws-cdk-lib";
import type {Construct} from "constructs";
import {ApNortheast1Stack} from "../../../../stacks/ap-northeast-1-stack";

export class PipelineApNorthEast1Stage extends Stage {
    constructor(scope: Construct, id: string, props?: StageProps) {
        super(scope, id, props);

        new ApNortheast1Stack(this, "APN1Stack", {});
    }
}
```

5. **Pipelineスタックの作成**
   `pipeline-infra-stack.ts` にて、`CodePipeline`
   を定義し、GitHub接続やsynth設定、ステージ追加などを記述。AWS公式の構成例に沿って、CodePipeline＋ShellStepで構築。pipelines.CodePipelineSource.connection()
   で GitHub と連携し、synth コマンドは ShellStep で明示。スタックを Stage にまとめ、addStage()
   でパイプラインに登録。将来的なマルチステージ（dev / prd）展開にもスムーズに対応できる構成。

```typescript
// lib/constructs/pipeline/pipeline-infra-stack.ts

import * as cdk from 'aws-cdk-lib';
import type {Construct} from 'constructs';
import {CodePipeline, ManualApprovalStep, ShellStep} from 'aws-cdk-lib/pipelines';
import * as iam from 'aws-cdk-lib/aws-iam';
import {pipelines} from "aws-cdk-lib";
import * as codebuild from 'aws-cdk-lib/aws-codebuild';
import {PipelineApNorthEast1Stage} from "./stages/ap-norheast-1-stage";

interface PipelineStackProps extends cdk.StackProps {
}

export class PipelineStack extends cdk.Stack {
    constructor(scope: Construct, id: string, props: PipelineStackProps) {
        super(scope, id, props);

        const pipeline = new CodePipeline(this, 'Pipeline', {
            synth: new ShellStep('Synth', {
                input: pipelines.CodePipelineSource.connection(`Nakamura-0709/cdk-pipeline-test`, "develop", {
                    // connectionArnは手順8で取得したものを埋め込む
                    connectionArn: "arn:aws:codeconnections:ap-northeast-1:AWS_ACCOUNT_ID:connection/CONNECTION_ID",
                }),
                commands: [
                    'cd cdk',
                    'npm ci',
                    // 公式ドキュメントには npm run build とあるが、cdk synth が失敗するため削除
                    'npx cdk synth'
                ],
                primaryOutputDirectory: 'cdk/cdk.out',
            }),
            // CodePipelineのデフォルトのBuildSpecを上書きし、Node 18ではなくNode 22を利用するように指定。
            synthCodeBuildDefaults: {
                partialBuildSpec: codebuild.BuildSpec.fromObject({
                    version: '0.2',
                    phases: {
                        install: {
                            'runtime-versions': {
                                nodejs: '22'
                            }
                        }
                    }
                })
            }
        });

        pipeline.addStage(new PipelineApNorthEast1Stage(this, 'DevPipelineAPNE1Stage', {
            env: {account: "AWS_ACCOUNT_ID", region: "ap-northeast-1"},
        }))

        pipeline.buildPipeline()
        // 権限が不足しているため、CodePipelineのIAMロールにポリシーを追加
        pipeline.synthProject.role?.addToPrincipalPolicy(new iam.PolicyStatement({
            actions: [
                "ec2:DescribeAvailabilityZones",
                "route53:ListHostedZonesByName"
            ],
            resources: ["*"]
        }));
    }
}
```

6. **エントリポイントの作成**
   `bin/cdk.ts` にて `PipelineStack` をAppに追加。今後別アカウントにデプロイすることを想定し、idを `Dev` としている。

```typescript
// bin/cdk.ts

#!/usr/
bin / env
node
import "source-map-support/register";
import * as cdk from "aws-cdk-lib";
import {PipelineStack} from "../lib/constructs/pipeline/infra/pipeline-infra-stack";

const app = new cdk.App();

new PipelineStack(app, "Dev", {
    env: {account: "AWS_ACCOUNT_ID", region: "ap-northeast-1"},
});

app.synth();
```

7. **GitHubリポジトリの作成とPush**
    - GitHubで新規リポジトリを作成
    - `git init` → `git remote add` → `git push`

8. **CodePipelineのGitHub接続設定**
    - AWSコンソールからGitHub Appを作成
    - GitHub上でCodePipelineのAppをインストール
    - 接続のARN（CodeConnectionsArn）を取得し、`pipeline-infra-stack.ts` に埋め込む

9. **CloudShellでの操作**
    - CloudShellを起動し、リポジトリを `git pull`
    - `cdk bootstrap` を実行（※クロスアカウント時は `--trust` を指定）
    - `cdk deploy` を実行してパイプラインをデプロイ

10. **デプロイの確認**
    - AWSコンソールからCodePipelineを確認
    - デプロイが成功していることを確認
    - CloudFormationのスタックも確認

## 公式ドキュメントにない発見・気づき

- インフラチームでのCDK Pipelineを利用すると、チーム内でのインフラ変更のトレーサビリティが向上する
    - GitHubのPRにCDKの変更が含まれるため、PRレビューでインフラ変更の内容を確認できる
    - デプロイ状況がAWSコンソールから確認できるため、デプロイの進捗を把握しやすい
