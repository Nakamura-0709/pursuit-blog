# AWS SAMを使ったAPI構築の手順

AWS SAMを使用してローカルなLambdaAPIの開発環境を用意する機会があったので、以下に手順を記載します。

この構成がDockerコンテナを利用することで、AWSとは関係ないローカルな開発環境を作れるらしい。
実際にAWS環境を使うとリソースコストがかかったり、仮に顧客の環境を利用する場合は他のリソースに影響しないとも限らない。（主にヒューマンエラー）
ローカルであることに越したことはない！

sam --version

## 1. sam initによるプロジェクト作成

まず、AWS SAM CLIを使用してプロジェクトを作成します。

### コマンド
```bash
sam init
```

### インタラクティブな質問への回答例

このあたりのテンプレートの選択は正直適当で構いません。
後述するディレクトリ構造の形になるように修正します。

## 2. ディレクトリ構造の作成

プロジェクト内で以下の構造を作成します。

### ディレクトリ構造
```
.
├── README.md
├── buildspec.yml
├── package.json
├── samconfig.toml
├── src
│   ├── getLambdaApi1
│   │   └── handlers
│   │       └── index.py
│   └── getLambdaApi2
│       └── handlers
│           └── index.py
└── template.yaml
```

---

## 3. template.yamlの記述

プロジェクトのSAMテンプレートに以下の内容を記述します。
EventsのTypeにApiを記載すれば、お手軽にAPIゲートウェイをトリガーにLambdaを起動することができる。
他にもS3などをトリガーにできる。
この場合は、Pathに基づいて異なるAPIゲートウェイのリソースへのリクエストをトリガーに各Lambdaが起動することになる。

```yaml
AWSTemplateFormatVersion: 2010-09-09
Description: SamTest-Api

Transform:
  - AWS::Serverless-2016-10-31

Resources:

  getLambdaApi1Function:
    Type: AWS::Serverless::Function
    Properties:
      Handler: src/getLambdaApi1/handlers/index.lambda_handler
      Runtime: python3.13
      Architectures:
        - x86_64
      MemorySize: 128
      Timeout: 900
      Description: Get getLambdaApi1
      Events:
        ApiGateway:
          Type: Api
          Properties:
            Path: /api/getLambdaApi1
            Method: GET

  getLambdaApi2Function:
    Type: AWS::Serverless::Function
    Properties:
      Handler: src/getLambdaApi2/handlers/index.lambda_handler
      Runtime: python3.13
      Architectures:
        - x86_64
      MemorySize: 128
      Timeout: 900
      Policies:
        - Statement:
            Effect: Allow
            Action:
              - secretsmanager:GetSecretValue
            Resource: arn:aws:secretsmanager:(region):(accountId):secret:(secretName)
      Description: Get getLambdaApi2
      Events:
        ApiGateway:
          Type: Api
          Properties:
            Path: /api/getLambdaApi2
            Method: GET
```

## 4. ハンドラーの記述

※ `AWS Secrets Manager`にすでに認証情報が登録済みであるとする。
ARN: `arn:aws:secretsmanager:(region):(accountId):secret:(secretName)`
```json
{
   "SERVICE_URL": "https://example.com/api",
   "SERVICE_API_KEY": "your-service-api-key"
}
```

以下の内容を`src/getLambdaApi1/handlers/index.py`に記述します。

```python
import json

def lambda_handler(event, context):
    # デバッグ用ログ出力
    print("Event received:", event)

    try:
        # 処理内容
        return {
            "statusCode": 200,
            "body": json.dumps({"message": "getLambdaApi1 Data Retrieved Successfully"})
        }
    except Exception as e:
        print(f"Error occurred: {str(e)}")
        return {
            "statusCode": 500,
            "body": json.dumps({"message": "Internal server error", "error": str(e)})
        }
```

以下の内容を`src/getLambdaApi2/handlers/index.py`に記述します。
こちらは先述したAWS Secrets Managerから認証情報を取得して返却するハンドラーを記述しています。（本番環境でやらないでね。）

```python
import boto3
import json
from botocore.exceptions import ClientError

def get_secret():
   secret_name = "test/service/api"
   region_name = "ap-northeast-1"

   session = boto3.session.Session()
   client = session.client(service_name='secretsmanager', region_name=region_name)

   try:
      response = client.get_secret_value(SecretId=secret_name)
      if 'SecretString' in response:
         return json.loads(response['SecretString'])
      else:
         raise Exception("Secret format not recognized.")
   except ClientError as e:
      print(f"Error retrieving secret: {e.response['Error']['Message']}")
      raise e

def lambda_handler(event, context):
   try:
      # Secrets Managerから認証情報を取得
      secret = get_secret()
      service_url = secret.get("SERVICE_URL", "URL not found")
      service_api_key = secret.get("SERVICE_API_KEY", "API key not found")

      # デバッグ用ログ出力
      print(f"SERVICE_URL: {service_url}")
      print(f"SERVICE_API_KEY: {service_api_key}")

      # 正常なレスポンスを返す
      return {
         "statusCode": 200,
         "body": json.dumps({
            "SERVICE_URL": service_url,
            "SERVICE_API_KEY": service_api_key
         })
      }

   except Exception as e:
      print(f"Error: {str(e)}")
      return {
         "statusCode": 500,
         "body": json.dumps({"error": str(e)})
      }
```

## 5. sam build

プロジェクトをビルドしてデプロイ準備を整えます。

### コマンド
```bash
sam build
```

ビルドが成功すると、`.aws-sam`ディレクトリが生成されます。

---

## 6. sam local start-apiでローカル環境構築

ローカル環境でAPIを起動してテストします。

### コマンド
```bash
sam local start-api
```

出力例:
```
Mounting getLambdaApi1Function at http://127.0.0.1:3000/api/getLambdaApi1 [GET]
Mounting getLambdaApi2Function at http://127.0.0.1:3000/api/getLambdaApi2 [GET]
```

### テスト
別のターミナルでcurlを使用してAPIをテストします。

#### getLambdaApi1
```bash
curl http://127.0.0.1:3000/api/getLambdaApi1
```

#### getLambdaApi2
```bash
curl http://127.0.0.1:3000/api/getLambdaApi2
```
