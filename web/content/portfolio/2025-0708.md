# CDKTFで動的な値が反映されない問題の解決

## 問題の概要

CDKTFを使用してインフラストラクチャを管理している際に、S3バケットポリシーで動的なCloudFrontディストリビューションIDを設定したが、`cdktf apply`で反映されない問題に遭遇しました。

## 初期の問題

```typescript
// 問題のあるコード
condition: [
    {
        test: "StringEquals",
        variable: "AWS:SourceArn",
        values: [
            "arn:aws:cloudfront::*:distribution/*",
        ],
    },
],
```

このコードでは、ワイルドカード形式のCloudFrontディストリビューションIDを使用していましたが、より具体的な動的な値に変更したいと考えていました。

## 問題の調査

### 1. 動的な値への変更

まず、ワイルドカード形式から動的な値に変更しました：

```typescript
// 変更後のコード
condition: [
    {
        test: "StringEquals",
        variable: "AWS:SourceArn",
        values: [
            `arn:aws:cloudfront::${config.awsAccountId}:distribution/${this.distribution.id}`,
        ],
    },
],
```

### 2. 反映されない問題

`cdktf apply`を実行しましたが、変更が反映されませんでした。差分を確認すると、以下のような実行計画が表示されました：

```
# aws_s3_bucket_policy.presentation-layer_bucket-policy-attachment_252BB3A6 will be updated in-place
~ resource "aws_s3_bucket_policy" "presentation-layer_bucket-policy-attachment_252BB3A6" {
    id     = "portfolio-web-site-static-files-prod"
  ~ policy = jsonencode(
      ~ {
          ~ Statement = [
              ~ {
                  ~ Condition = {
                      ~ StringEquals = {
                          ~ "AWS:SourceArn" = "arn:aws:cloudfront::*:distribution/EXAMPLE123" -> "arn:aws:cloudfront::*:distribution/*"
                        }
                    }
                  }
                ]
              }
            )
          }
        )
```

この差分は、具体的な値からワイルドカード形式に変更しようとしていることを示していました。これは期待していた動作と逆でした。

### 3. 生成ファイルの削除

問題を解決するために、CDKTFの生成ファイルを削除してクリーンアップを行いました：

```bash
# 生成ファイルの削除
rm -rf cdktf.out .gen main.js main.d.ts tsconfig.tsbuildinfo

# 状態ファイルの削除
rm -f terraform.*.tfstate* .terraform.lock.hcl
```

## 根本原因

問題の根本原因は、CDKTFの生成ファイル（`cdktf.out`、`.gen`、`main.js`、`main.d.ts`、`tsconfig.tsbuildinfo`）が古い状態をキャッシュしていたことでした。これらのファイルが存在する限り、CDKTFは新しいコードの変更を正しく反映せず、古い設定を維持していました。

## 解決策

### 1. TypeScriptエラーの修正

まず、未使用変数によるTypeScriptエラーを修正しました：

```typescript
// 修正前
const bucketPolicyAttachment = new S3BucketPolicy(
    this,
    "bucket-policy-attachment",
    {
        bucket: this.staticBucket.id,
        policy: bucketPolicy.json,
        dependsOn: [this.distribution, bucketPolicy],
    },
);

// 修正後
new S3BucketPolicy(this, "bucket-policy-attachment", {
    bucket: this.staticBucket.id,
    policy: bucketPolicy.json,
    dependsOn: [this.distribution, bucketPolicy],
});
```

### 2. 生成ファイルの削除による解決

生成ファイルを削除した後、再度`cdktf diff`を実行すると、動的な値が正しく反映されるようになりました：

```bash
ENV=prod AWS_PROFILE=personal npx cdktf diff
```

### 3. 解決後の差分確認

生成ファイルを削除した後、`cdktf diff`を実行すると、今度は正しい方向の差分が表示されました：

```
# aws_s3_bucket_policy.presentation-layer_bucket-policy-attachment_252BB3A6 will be updated in-place
~ resource "aws_s3_bucket_policy" "presentation-layer_bucket-policy-attachment_252BB3A6" {
    id     = "portfolio-web-site-static-files-prod"
  ~ policy = jsonencode(
      ~ {
          ~ Statement = [
              ~ {
                  ~ Condition = {
                      ~ StringEquals = {
                          ~ "AWS:SourceArn" = "arn:aws:cloudfront::*:distribution/EXAMPLE123" -> "arn:aws:cloudfront::123456789012:distribution/EXAMPLE123"
                        }
                    }
                  }
                ]
              }
            )
          }
        )
```

今度は、ワイルドカード形式から具体的な値に変更する正しい差分が表示されました。

## 結果

生成ファイルを削除した後、再度`cdktf diff`を実行した結果：

- **コード**: 動的な値を使用（`arn:aws:cloudfront::${config.awsAccountId}:distribution/${this.distribution.id}`）
- **生成されたTerraform**: 動的な値が正しく反映される
- **AWS上の実際の状態**: ワイルドカード形式から動的な値に変更される

これで、ワイルドカード形式（`arn:aws:cloudfront::*:distribution/*`）から動的な値に変更され、コードとTerraformの生成コードが一致し、`cdktf apply`で正しく変更が反映されるようになりました。

## 学んだ教訓

1. **CDKTFの生成ファイル**: 生成ファイルが古い状態をキャッシュしている場合、新しい変更が反映されない
2. **状態ファイルの重要性**: 状態ファイルを削除しても、AWS APIを通じて現在の状態を取得できる
3. **差分の確認**: `cdktf diff`を使用して、コードと実際のインフラストラクチャの差分を正確に把握する
4. **TypeScriptエラー**: 未使用変数は削除するか、適切に使用する

## 今後の対策

1. **生成ファイルの管理**: 変更が反映されない場合は、生成ファイルを削除してクリーンアップする
2. **定期的な差分確認**: 変更前に必ず`cdktf diff`で差分を確認する
3. **状態ファイルの管理**: 必要に応じて状態ファイルをクリーンアップする

この経験を通じて、CDKTFでのインフラストラクチャ管理における問題解決の手順を確立できました。
