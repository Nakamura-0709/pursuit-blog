# CDKTF + Next.js デプロイ時の障害と解決策

## 概要

AWS CDK for Terraform (CDKTF) と Next.js を使用したポートフォリオサイトのデプロイ時に、いくつかの障害が発生しました。この記事では、それらの障害と解決策について詳しく解説します。

## 発生した障害

### 1. CloudFront からの S3 アクセス拒否 (403 Forbidden)

#### 問題の詳細
- **症状**: CloudFront URL にアクセスすると 403 Forbidden エラーが発生
- **エラーメッセージ**: `HTTP/2 403 content-type: application/xml server: AmazonS3`
- **原因**: S3 バケットポリシーの条件が CloudFront の実際の ARN と一致しない

#### 問題の技術的背景

CloudFront から S3 バケットにアクセスする際、S3 バケットポリシーで CloudFront からのアクセスを許可する必要があります。しかし、以下の設定では正しく動作しませんでした：

```json
// 問題のある設定
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::your-bucket-name/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::*:distribution/*"
        }
      }
    }
  ]
}
```

この設定の問題点：
- ワイルドカード `*` が文字列として扱われる
- 実際の CloudFront ARN と完全一致しない
- AWS の条件評価で失敗する

#### 解決策

正確な CloudFront ARN を指定することで解決しました：

```json
// 正しい設定
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::your-bucket-name/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::AWS_ACCOUNT_ID:distribution/DISTRIBUTION_ID"
        }
      }
    }
  ]
}
```

#### 確認方法

デプロイ後に以下のコマンドでアクセスを確認できます：

```bash
# CloudFront URL へのアクセステスト
curl -I https://your-cloudfront-domain.cloudfront.net

# 正常な場合のレスポンス
HTTP/2 200
content-type: text/html
x-cache: Miss from cloudfront
```

### 2. TypeScript 型エラー

#### 問題の詳細
- **症状**: Next.js 15 へのアップグレード後に型エラーが発生
- **エラーメッセージ**: `Type 'Promise<{ slug: string }>' is not assignable to type '{ slug: string }'`
- **原因**: Next.js 15 でルートパラメータが Promise 型に変更された

#### 問題の技術的背景

Next.js 15 では、App Router のルートパラメータが非同期処理に変更されました。これにより、以下のような型エラーが発生します：

```typescript
// Next.js 14 以前の書き方（エラーになる）
export default function LifePage({ params }: { params: { slug: string } }) {
  const { slug } = params;
  // ...
}
```

#### 解決策

ルートパラメータを非同期で処理するように修正しました：

```typescript
// Next.js 15 での正しい書き方
export default async function LifePage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  // ...
}
```

#### 影響を受けるファイル

以下のファイルで同様の修正が必要でした：

```typescript
// app/life/[slug]/page.tsx
export default async function LifePage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  // ...
}

// app/portfolio/[slug]/page.tsx
export default async function PortfolioPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  // ...
}
```

#### 型定義の更新

型定義ファイルも更新が必要でした：

```typescript
// types/article.ts
export interface ArticleParams {
  slug: Promise<string>;
}
```

## 学んだ教訓

### 1. AWS SourceArn の重要性
CloudFront から S3 へのアクセス制御では、正確な ARN の指定が重要です。ワイルドカードの使用は予期しない動作を引き起こす可能性があります。

### 2. 型安全性の重要性
Next.js のアップグレード時には、型の変更に注意が必要です。特に非同期処理に関連する型の変更は、アプリケーション全体に影響する可能性があります。

### 3. デバッグの重要性
- **CloudFront の設定確認**: AWS CLI を使用した詳細な設定確認
- **型エラーの早期発見**: TypeScript コンパイラの活用
- **段階的な修正**: 一度に多くの変更を行わず、小さな単位で修正

## 結果

これらの修正により、以下の成果を得ることができました：

- ✅ CloudFront からの S3 アクセスが正常に動作
- ✅ TypeScript 型エラーが解決
- ✅ セキュアなアクセス制御が実現
- ✅ Next.js 15 への正常なアップグレード
