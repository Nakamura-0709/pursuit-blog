# バックエンド開発者のためのDynamoDB設計と実装ノウハウ

## 概要

本記事は、Node.js（TypeScript）でDynamoDBを活用したサーバーレスなバックエンドAPIを設計・実装する際の実践的なポイントをまとめたものです。API設計・テーブル設計・実装例・運用Tipsまで、実際のポートフォリオWebサイト開発を通じて得た知見を共有します。

## なぜDynamoDBを選択したか

- **サーバーレス&スケーラブル**: インスタンス管理不要、アクセス増加にも自動対応。
- **コスト最適化**: オンデマンド課金で個人開発や小規模サービスに最適。
- **Node.jsとの親和性**: AWS SDK v3でTypeScriptから型安全に操作可能。

## API設計とDynamoDBの関係

DynamoDBはRDBと異なり、NoSQLのため「アクセスパターン駆動設計」が重要です。APIのユースケースごとに必要なデータ取得・保存パターンを明確にし、シンプルなテーブル設計を心がけます。

### 例：お問い合わせAPI
- **POST /api/contact**: お問い合わせデータを新規登録
- **GET /api/contact**: お問い合わせ一覧取得（管理者用）
- **GET /api/contact/:id**: お問い合わせ詳細取得
- **PUT /api/contact/:id/status**: ステータス更新

## テーブル設計例（portfolio-contacts）

| 属性名      | 型   | 用途                |
|:------------|:-----|:--------------------|
| id          | S    | パーティションキー（contact_yyyymmdd_xxx形式） |
| name        | S    | 名前                |
| email       | S    | メールアドレス      |
| subject     | S    | 件名                |
| message     | S    | メッセージ本文      |
| recaptchaToken | S | reCAPTCHAトークン   |
| status      | S    | ステータス（new等） |
| createdAt   | S    | 作成日時（ISO8601） |

- **パーティションキーのみ**のシンプル設計。複雑な検索要件がなければGSIは不要。
- IDは`contact_タイムスタンプ_ランダム`形式で生成し、ユニーク性を担保。
- オンデマンド課金（BillingMode: PAY_PER_REQUEST）でコストを最小化。

## TypeScript/Node.jsでのDynamoDB操作例

DynamoDBの操作はAWS SDK v3の`@aws-sdk/lib-dynamodb`を利用します。

```ts
import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import { DynamoDBDocumentClient, PutCommand, GetCommand } from "@aws-sdk/lib-dynamodb";

const client = new DynamoDBClient({ region: "ap-northeast-1" });
const docClient = DynamoDBDocumentClient.from(client);

// データ登録
await docClient.send(new PutCommand({
  TableName: "portfolio-contacts",
  Item: {
    id: "contact_20240629_xxx",
    name: "テストユーザー",
    email: "test@example.com",
    subject: "テスト件名",
    message: "テストメッセージ",
    status: "new",
    createdAt: new Date().toISOString(),
  },
}));

// データ取得
const result = await docClient.send(new GetCommand({
  TableName: "portfolio-contacts",
  Key: { id: "contact_20240629_xxx" },
}));
console.log(result.Item);
```

## ロギング・エラーハンドリング

- **winston**でAPIリクエストやDynamoDB操作のログを出力し、障害時のトラブルシュートを容易に。
- 例外発生時はloggerで詳細を記録し、APIレスポンスは汎用的なエラーメッセージに統一。

```ts
import logger from "../config/logger";

try {
  // DynamoDB操作
} catch (error) {
  logger.error("Failed to create contact", { error });
  throw error;
}
```

## 運用・コスト最適化Tips

- **無料枠の活用**: 月25GBストレージ、200万リクエストまで無料枠で運用可能。
- **SSE（暗号化）有効化**: セキュリティ要件を満たすため、SSESpecificationで暗号化を有効化。
- **テーブル設計はシンプルに**: 複雑な検索要件がなければパーティションキーのみで十分。
- **CloudWatch Logs連携**: LambdaやAPI Gatewayと組み合わせて監視・アラートも容易。
- **バックアップ**: 必要に応じてオンデマンドバックアップやPoint-in-Time Recoveryを有効化。

## まとめ

DynamoDBは、Node.jsバックエンド開発において「コスト最適化」「スケーラビリティ」「運用負荷低減」を実現できる強力な選択肢です。API設計とテーブル設計をセットで考え、TypeScriptで型安全に実装・運用することで、堅牢かつ拡張性の高いサーバーレスバックエンドを構築できます。
